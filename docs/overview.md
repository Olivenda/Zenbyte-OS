# Platin Zenbyte — OS Overview

## What is Platin Zenbyte?

Platin Zenbyte is a lightweight, experimental Linux distribution built for
simplicity, performance, and full transparency. Every component — from the
init script to the package manager — is written and maintained in this
repository. There are no black boxes.

The OS is assembled from existing binary packages (Fedora RPMs, repackaged via
`zbpm-build`) but the system layer itself — boot, init, installer, package
management — is entirely custom.

## Design Goals

- **Minimal surface area.** The live rootfs fits comfortably in a cpio
  initramfs. Only what is explicitly included is present.
- **Understandable init.** PID 1 is a plain Bash script (`rootfs/init`) with
  no dependencies on any init framework until systemd is exec'd at the end.
- **Signed packages.** `zbpm` refuses to install anything not signed by the
  repository key. The trust anchor is a GPG key you generate and control.
- **Reproducible builds.** The initramfs and ISO are produced by deterministic
  Makefile rules with no host-state leakage.

## Repository Layout

```
Zenbyte-OS/
  rootfs/          Live filesystem tree (packed into init.cpio)
    init           PID 1 — mounts, network, boot menu, execs systemd
    install.sh     Graphical text installer (launched from the boot menu)
    usr/bin/zbpm   Package manager
    var/lib/zbpm/  zbpm state: installed list, manifests, post-install hooks
  iso/
    boot/grub/grub.cfg   GRUB config for the live ISO
  build/
    bzImage        Compiled kernel (not tracked in git)
    zenbyte.iso    Output ISO (generated by `make iso`)
  tools/           Host-side build & publish tooling (zbpm-build, zbpm-repo, …)
  docs/            This documentation
  Makefile         Top-level build orchestration
  init.cpio        Generated initramfs (output of `make initramfs`)
```

## Component Overview

### Boot Flow

```
GRUB2
  └─ loads bzImage + init.cpio
       └─ rootfs/init  (PID 1, Bash)
            ├─ mounts proc / sysfs / devtmpfs / devpts / run
            ├─ brings up first network interface (DHCP, 10-second timeout)
            ├─ displays boot menu (EN or DE, selected via kernel cmdline lang=)
            │    1) Boot system  → exec systemd
            │    2) Install      → /install.sh, then reboot
            │    3) Emergency    → exec bash
            └─ exec /usr/lib/systemd/systemd
```

### Package Manager — zbpm

`zbpm` is a minimal package manager written in Bash. It installs packages from
a static HTTPS repository:

- Fetches `<pkg>.tar.gz` from the configured mirror list (`/etc/zbpm/mirrors`).
- Verifies SHA-256 checksum and detached GPG signature before touching the
  filesystem.
- Extracts files only into paths inside the configured prefix allow-list
  (`/usr/`, `/etc/`, `/opt/`, `/var/lib/zbpm/scripts/`).
- Runs `META/postinst` (if present) after successful extraction.
- Records installed packages under `/var/lib/zbpm/installed/` and file
  manifests under `/var/lib/zbpm/manifests/`.

See [package-repo-schema.md](package-repo-schema.md) for the wire format and
[building-packages.md](building-packages.md) for the host build toolchain.

### Installer — install.sh

A fully interactive text installer that supports:

- **UEFI** (GPT + ESP) and **BIOS** (MBR) out of the box.
- Filesystem choice: ext4, btrfs, or xfs.
- Automatic or manual swap sizing.
- Root password + optional unprivileged user (added to `wheel` / sudo).
- Locale, keyboard layout, timezone selection.
- zbpm mirror configuration (fetches the signing key automatically).
- Optional XFCE4 desktop, installed on first boot via a systemd oneshot unit.

The installer is launched from option 2 in the init boot menu, or can be run
standalone as `./install.sh` inside the live environment.

### Kernel

The kernel binary (`build/bzImage`) is not tracked in git due to size. It is
built separately and also available as a `zbpm` package (`zbpm install kernel`),
which installs via a post-install hook that re-points `/boot/vmlinuz` and
generates the initramfs with dracut.
