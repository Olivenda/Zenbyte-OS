# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Zenbyte-OS is an experimental custom Linux distribution built from a Fedora-derived rootfs with custom Bash-based tooling: a PID-1 init, an interactive disk installer, and a from-scratch package manager (`zbpm`).

## Build System

A top-level `Makefile` orchestrates the OS-level builds. Common targets:

```bash
make initramfs   # pack rootfs/ -> init.cpio (gzip-compressed cpio)
make iso         # assemble build/zenbyte.iso (needs grub2-mkrescue)
make lint        # shellcheck on init, install.sh, zbpm, and post-install hooks
make clean       # drop generated artifacts
```

The kernel itself is **not** built by the Makefile. Drop a compiled `bzImage` at `build/bzImage`; the kernel source tree under `Kernel/` is gitignored.

Third-party C packages in `Packages/` use their own build systems:

```bash
cd Packages/lua && make linux && make install
cd Packages/htop && ./autogen.sh && ./configure && make
```

## Repository Architecture

```
rootfs/                # Complete Linux root filesystem (the OS itself)
  init                 # PID-1 Bash init (mounts, network, boot menu)
  install.sh           # Disk installer v3.0 (UEFI + BIOS, GPT/MBR)
  usr/bin/zbpm         # zbpm v2.x — signature-verifying package manager
  usr/lib/systemd/system/
    zbpm-firstboot.service   # Hardened first-boot installer for the desktop
  etc/zbpm/            # Mirror list, signing keyring, runtime config
  var/lib/zbpm/        # Installed-package DB, manifests, post-install hooks
build/                 # Compiled kernel (bzImage) + Makefile output
Packages/              # Vendored source packages (htop, lua, ...)
iso/                   # ISO boot directory (grub.cfg only — others gitignored)
docs/                  # package-repo-schema.md, overview.md
init.cpio              # Packed rootfs (regenerated by `make initramfs`)
```

## Boot Flow

1. GRUB (from `iso/boot/grub/grub.cfg`) loads `bzImage` and `init.cpio`.
2. The kernel execs `rootfs/init` as PID 1.
3. `init` mounts `proc`/`sysfs`/`devtmpfs`/`devpts`/`tmpfs`, brings up the first non-loopback NIC with a bounded DHCP timeout, then presents a menu (Boot / Install / Emergency shell).
4. **Install** path runs `install.sh`, then offers reboot vs. shell.
5. **Boot** path execs `/usr/lib/systemd/systemd`. If that binary is missing, init drops to an emergency shell instead of panicking.

## zbpm — package manager (v2.x)

Bash, single file: `rootfs/usr/bin/zbpm`. Key properties:

- **Signature-verified** by default: refuses to install without a SHA-256 file *and* a detached GPG signature verifiable against `/etc/zbpm/keys/zbpm.{kbx,gpg}`. Override with `ZBPM_REQUIRE_SIGNATURE=0` or `--no-verify` only for local development.
- **Safe extraction**: tarballs are unpacked to a staging dir; every member's path is validated against `ZBPM_INSTALL_PREFIX_ALLOW` before any file is written under `/`. The same allow-list is enforced again at remove-time on every manifest entry.
- **Atomic installs**: a `.partial` sentinel is written before extraction and cleared on success; `zbpm check` reports orphaned partials.
- **Locked**: a single `mkdir`-based lock in `$ZBPM_DB/.lock` prevents concurrent runs.
- **Mirror failover**: `/etc/zbpm/mirrors`, one URL per line, tried top-to-bottom.
- **Cycle-safe deps**: tracks an in-stack set during recursion; bounded by `ZBPM_MAX_DEPS_DEPTH`.
- **Non-interactive friendly**: `-y/--yes` plus auto-yes when stdin is not a TTY (so the firstboot service does not stall).
- Commands: `install`, `reinstall`, `remove [--force]`, `sync`, `upgrade`, `update` (=sync+upgrade), `list`, `search`, `info`, `files`, `owns`, `depends`, `hold`, `unhold`, `clean`, `log`, `check`, `version`, `help`.

Repository wire format is documented in `docs/package-repo-schema.md`. Defaults and overridable settings live in `/etc/zbpm/zbpm.conf`.

## Installer (v3.0)

`rootfs/install.sh`. Detects UEFI vs BIOS via `/sys/firmware/efi`, validates every input (hostname, username, timezone, disk name, swap size), uses GPT+ESP on UEFI or MBR on BIOS, supports ext4 / btrfs / xfs, sizes swap automatically based on RAM, writes a UUID-based `/etc/fstab`, sets locale + keymap + timezone, and creates the user via `wheel`-group sudo (validated with `visudo -c`).

Passwords are passed to `chpasswd --root` via a here-string and the variables are `unset` immediately after — never echoed to the command line and never visible in `/proc/<pid>/environ` past that point.

The legacy `selinux=0` and `init=/bin/bash` recovery backdoor are gone. The XFCE first-boot path uses the shipped systemd unit (sandboxed; `NoNewPrivileges`, `ProtectKernel*`, `RestrictSUIDSGID`, etc.) and reads `/etc/zbpm/firstboot.user` to autologin the *user*, not root.

## Common Pitfalls

- The `/etc/zbpm/keys/` directory is empty by design — it must contain a real `zbpm.gpg` keyring before `zbpm install` will succeed in production. Local dev can run `ZBPM_REQUIRE_SIGNATURE=0`.
- After editing anything under `rootfs/`, run `make initramfs` to regenerate `init.cpio`. The pre-built `init.cpio` checked in at the repo root is a snapshot.
- The Fedora-derived `rootfs/etc/lightdm/lightdm.conf.rpmsave` is a leftover from the parent distro; the canonical lightdm config is now written by `xfce4-desktop.post` at first boot.
